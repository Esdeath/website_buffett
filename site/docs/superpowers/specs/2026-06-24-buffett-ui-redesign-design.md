# 巴菲特知识库 UI 重设计稿

日期：2026-06-24  
方向：编辑桌面 / 杂志式阅读  
目标：优先提升长文阅读体验，同时保留知识检索、来源回溯和关系跳转能力。

## 1. 背景

当前站点已经具备完整的知识库能力：分类、关键词、图谱、来源矩阵、反向链接、搜索和文章视图都可用。现阶段的问题不是功能缺失，而是阅读主线不够清晰。

目前页面更像一个“信息聚合站”，而不是一个“经过编辑整理后的阅读刊物”。

主要体感问题：

- 首页入口偏散，用户需要自己决定从哪里开始读。
- 文章页里“阅读 / 图谱 / 来源”并列，阅读主任务没有得到足够强化。
- 左右侧栏都承担了较重的信息密度，正文的视觉优先级不够稳定。
- 版式整体偏工具站，缺少杂志式的节奏、留白和层级。

## 2. 设计目标

### 2.1 核心目标

把站点从“知识列表站”改成“可持续阅读的编辑型知识库”。

### 2.2 具体目标

- 让用户第一眼知道“先读什么”。
- 让正文成为视觉中心。
- 让来源、关键词、相关条目作为阅读辅助，而不是平级主内容。
- 让页面整体更像专题文章、研究简报或编辑后的阅读刊物。

### 2.3 不做的事

- 不重做信息架构。
- 不去掉图谱、来源矩阵、关键词和反向链接。
- 不引入花哨动效或重资产视觉装饰。
- 不把站点改成单纯的内容博客。

## 3. 方向定义

选择的方案是“编辑桌面”。

它的核心不是把页面做空，而是把信息摆放成一种明确的阅读顺序：

1. 正文先读。
2. 右侧辅助阅读区用于理解上下文。
3. 次级视图用于查看关系、图谱和来源。

这套方向适合当前站点，因为知识库内容本身是研究型材料，天然需要“主文 + 脚注 + 关联阅读”的结构。

## 4. 页面级改造

### 4.1 首页

首页要从“分类目录”变成“阅读入口页”。

建议结构：

- 顶部短引导，明确站点用途和阅读方式。
- 一个主要入口区，展示“从分类总论开始”或“最近可读的专题”。
- 一个次级入口区，列出全部分类，但降低视觉权重。
- 可选的“继续阅读”区，用于承接用户上一次的阅读路径。

视觉效果：

- 首页标题更像刊物封面标题。
- 分组之间使用更明显的留白。
- 分类列表不再像纯目录，而更像栏目索引。

### 4.2 文章页

文章页是重设计重点。

建议结构：

- 顶部保留标题，但强化标题与分类的层级差异。
- 默认视图固定为“阅读”。
- “图谱”和“来源”作为次级标签页，继续保留，但不抢夺首屏焦点。
- 正文区域采用更窄的阅读宽度，让长文更易扫读。
- 右侧栏变成稳定的阅读辅助区，包含关键词、相关条目、反向链接和必要的来源提示。

阅读区的重点：

- 提高标题、段落、引文和小标题的层级区分。
- 让 quote、note、列表和表格在视觉上更清楚。
- 控制正文宽度，避免一行过长。

辅助区的重点：

- 关键词仍然存在，但不需要占据过高视觉权重。
- 相关文章和反向链接合并为“继续阅读”型模块。
- 来源信息保持可发现，但不压过正文。

### 4.3 图谱与来源视图

这两个视图保留，但表现为“阅读后的探索工具”。

原则：

- 默认不打断阅读。
- 切换时保持与正文一致的视觉系统。
- 页面标题和上下文要继续明确，避免像跳到另一个产品。

## 5. 信息层级

推荐的层级顺序如下：

1. 标题
2. 分类 / 类型
3. 正文
4. 相关关键词
5. 来源与证据
6. 图谱与延伸阅读

这意味着：

- 正文永远优先于关系网络。
- 关系网络优先于工具性展示。
- 工具不消失，但必须服务于阅读。

## 6. 视觉系统

### 6.1 气质

“杂志式阅读”不是轻飘的出版物风，而是有克制感的研究刊物气质。

关键词：

- 安静
- 克制
- 可靠
- 稳定
- 研究感

### 6.2 版式

建议方向：

- 正文列宽更窄。
- 页面整体留白增大。
- 右侧辅助区保持固定宽度，增强阅读秩序。
- 首页和文章页共享同一套节奏，不让页面跳变太大。

### 6.3 字体与排版

- 保留现有中文衬线气质，但提升标题与正文的层次。
- 标题可以更粗、更紧凑。
- 正文行距保持舒适，段落之间留出更清楚的呼吸空间。
- 引文、列表和表格的样式应明显区别于正文。

### 6.4 色彩

建议维持当前偏纸张、偏墨色的方向，但做得更统一：

- 背景继续保持纸感。
- 主文本使用深墨色。
- 链接保持低饱和绿色或接近墨绿的强调色。
- 辅助信息使用更柔和的灰绿或棕灰。

目标不是变得更花，而是更像被认真编辑过的材料。

## 7. 组件策略

### 7.1 Sidebar

左侧栏从“导航树”变成“稳定目录 + 搜索入口”。

调整重点：

- 保留可展开分类。
- 降低列表的视觉噪音。
- 当前文章高亮更明确，但不需要过度装饰。
- 搜索入口更像工具，而不是主视觉焦点。

### 7.2 KeywordPanel

关键词面板改成更像“文末标签区”。

建议：

- 关键词块收紧。
- 标签更统一。
- 相关条目和来源类型并入同一个辅助阅读组，减少碎片化感。

### 7.3 Backlinks

反向链接从“技术模块”变成“继续阅读”。

建议文案和排版更接近编辑推荐，而不是系统输出。

### 7.4 SourceMatrix

来源矩阵保留，但弱化默认曝光。

建议：

- 放在来源视图中作为重点。
- 在阅读视图里只保留摘要式入口或提示。

### 7.5 GraphView

图谱保留为探索工具，使用时强调“从文章延伸出去”，而不是“替代正文阅读”。

## 8. 首页与文章页的关系

首页负责解决“从哪里开始读”。

文章页负责解决“怎么读得更久、更稳”。

这两个页面之间需要形成一致体验：

- 首页提供阅读入口。
- 文章页提供深读环境。
- 两者都属于同一套编辑型系统，不应出现明显风格割裂。

## 9. 响应式策略

移动端要优先保证阅读，不要试图复制桌面三栏结构。

建议：

- 桌面端使用三栏。
- 平板端收缩右侧栏，必要时折叠为下方模块。
- 手机端改为单栏，先正文，后辅助信息，最后工具视图。

移动端的优先级：

1. 正文
2. 关键词与相关条目
3. 来源
4. 图谱

## 10. 可访问性要求

- 保持足够的颜色对比。
- 所有交互元素都需要明确 hover / focus 状态。
- 标签页与展开目录要可通过键盘操作。
- 阅读区标题层级必须语义正确，便于屏幕阅读器导航。

## 11. 风险与约束

### 11.1 风险

- 如果侧栏过弱，知识库的“可探索性”会下降。
- 如果首页过度杂志化，用户可能误以为这是内容站而不是知识库。
- 如果正文宽度过窄，长文会变成碎片化阅读。

### 11.2 应对

- 侧栏保留强搜索和清晰目录。
- 首页仍要明确分类入口。
- 正文宽度控制在舒适但不过窄的范围。

## 12. 验收标准

这次重设计完成后，应该满足以下判断：

- 用户打开首页时能立刻知道“从哪里开始读”。
- 用户进入文章页时，第一视觉焦点是正文而不是工具。
- 用户在阅读过程中能方便地找到关键词、相关条目和来源。
- 页面整体看起来更像经过编辑整理的阅读刊物，而不是普通文档站。
- 桌面与移动端都能保持稳定的阅读体验。

## 13. 实施顺序建议

1. 先改全局 tokens 和基础排版。
2. 再重做 BaseLayout 的三栏节奏。
3. 接着重排文章页的默认阅读视图。
4. 然后收敛 Sidebar、KeywordPanel 和 Backlinks 的视觉权重。
5. 最后调整首页入口结构。

## 14. 结论

这次 UI 重设计不追求炫技，核心是把站点的阅读主线拉直。

最终目标不是“页面更漂亮”，而是让它更像一本可以长期阅读、反复回看的编辑型知识刊物。
