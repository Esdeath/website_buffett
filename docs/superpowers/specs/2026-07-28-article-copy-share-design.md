# 文章复制分享功能设计

## 目标

为站内所有文章页提供“复制文章”按钮，包括解读/关键词文章和原始资料文章。复制结果应保留文章结构，并在内容顶部和底部显示“巴菲特知识库”及当前文章的绝对链接，便于读者在站外分享时保留出处。

## 范围

- 覆盖 `/keywords/`、`/articles/` 和 `/sources/` 下的文章详情页。
- 只复制当前 `<article>` 的阅读内容。
- 不复制站点导航、视图切换、图谱、来源面板、侧栏或复制按钮本身。
- 不增加社交平台分享、图片导出或 Markdown 下载功能。

## 用户界面

- 在文章标题和分类信息附近显示一个带复制图标的“复制文章”按钮。
- 按钮样式沿用现有站点的颜色、边框和圆角规范，并满足触控尺寸要求。
- 复制成功后，按钮短暂显示“已复制”，随后恢复。
- 复制失败时，按钮短暂显示“复制失败”，不使用阻塞式弹窗。
- 状态变化通过可访问的 live region 告知辅助技术。

## 剪贴板内容

现代浏览器中同时写入两种 MIME 类型：

- `text/html`：保留标题、段落、强调、列表、引用、表格和正文链接等语义格式。
- `text/plain`：为纯文本编辑器提供整洁的回退内容。

两种格式都遵循相同的内容顺序：

1. 顶部出处：站点名称“巴菲特知识库”和当前文章链接。
2. 完整文章正文，包括页面上的文章标题与分类。
3. 底部出处：再次显示站点名称和当前文章链接。

生成复制内容时，把正文内的相对 `href` 和 `src` 转换为基于当前站点的绝对 URL，确保内容粘贴到站外后仍能访问原目标。复制过程基于文章 DOM 的克隆，不修改当前页面。

## 组件与数据流

新增一个复用的 Astro 组件，由两套文章模板共同使用。组件接收文章容器选择器、站点名称和当前规范链接；客户端脚本在用户点击时读取并克隆目标文章，构造 HTML 与纯文本载荷，然后调用剪贴板 API。

内容构造逻辑放在独立模块中，使以下职责与按钮 DOM 事件分离：

- 构造首尾出处。
- 组合文章 HTML 和纯文本。
- 规范化内容中的 URL。

按钮组件只负责定位文章、调用构造逻辑、写入剪贴板及呈现状态。

## 兼容性与错误处理

- 优先使用 `navigator.clipboard.write()` 和 `ClipboardItem` 同时写入 HTML 与纯文本。
- 浏览器不支持富文本剪贴板时，回退到 `navigator.clipboard.writeText()`。
- API 不可用或权限被拒绝时显示“复制失败”，页面保持可用，控制台不产生未处理异常。
- 每次点击都使用当前页面 URL，避免构建环境和正式域名不一致。

## 测试与验收

自动化测试覆盖：

- HTML 与纯文本内容都包含两处站点名称和当前文章链接。
- 文章 HTML 结构保留在首尾出处之间。
- 正文内相对链接和资源地址转换为绝对 URL。
- 富文本 API 不可用时调用纯文本回退。
- 两类文章模板都渲染复制按钮并指向各自文章容器。

完成实现后运行单元测试、内容校验和生产构建，并在桌面与移动端视口检查：按钮不遮挡标题、不引发布局跳动，成功与失败状态文字均可完整显示。
