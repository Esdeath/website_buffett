## 4. 数据模型和文件格式

### 4.1 关键词注册表格式

文件：`docs/keyword-registry.md`

目标：全站关键词唯一注册表，所有 `[[关键词]]` 都必须能在这里找到 canonical 目标。

表头：

```markdown
| 关键词 | slug | 分类 | 词条路径 | 别名 | 状态 |
| --- | --- | --- | --- | --- | --- |
```

字段规则：

- [ ] `关键词` 使用中文 canonical 名称。
- [ ] `slug` 使用小写拼音或英文短横线。
- [ ] `分类` 使用 11 个分类之一。
- [ ] `词条路径` 指向 canonical 词条页。
- [ ] `别名` 记录英文名、简称、近义表达。
- [ ] `状态` 使用统一状态值。

统一状态：

- [ ] `未开始`
- [ ] `找材料中`
- [ ] `已建来源矩阵`
- [ ] `已选主引用`
- [ ] `初稿完成`
- [ ] `已核验`

示例：

```markdown
| 护城河 | hu-cheng-he | 核心哲学 | buffett/articles/keywords/hu-cheng-he.md | Economic Moat, 经济护城河 | 已核验 |
| 安全边际 | an-quan-bian-ji | 核心哲学 | buffett/articles/keywords/an-quan-bian-ji.md | Margin of Safety | 已核验 |
| GEICO | geico | 公司 | buffett/articles/companies/geico.md | 盖可保险 | 未开始 |
```

## 6. 单篇文章硬性要求

每篇文章必须包含：

- [ ] 1 个中心问题。
- [ ] 5-7 句来自 `buffett/` 的主引用。
- [ ] 3-5 个关联关键词。
- [ ] 5 个左右案例。
- [ ] 5 个左右常见误解。
- [ ] 5 个左右延伸阅读或相关主题。
- [ ] 每个案例、误解、延伸主题有 1-3 句解释。
- [ ] 每个关键判断能回溯到 `buffett/` 的具体文章、年份或段落。
- [ ] 正文首次出现的重要关键词使用 `[[关键词]]` 标记。
- [ ] 文章有完整 frontmatter。
- [ ] 文章保存到 `buffett/articles/` 下正确分类目录。

> **结构弹性（2026-06-22 决策）**：以上是必备的「内容要素」，不是固定小节名。文章可以用更贴合主题的小节标题（如《GEICO》用「GEICO 的商业模型」「伯克希尔为什么买下 GEICO」）来承载 §7 模板的意图，不必照搬通用小节名——主题化标题通常优于通用名。具体规则：
>
> - 文末的 `## 和其他关键词的关系`（列出 3-5 个相关关键词/主题，每条配 1-3 句说明并用 `[[关键词]]` 链接）**同时满足**「3-5 个关联关键词」与「5 个左右延伸阅读或相关主题」两项要求，无需再单列 `## 延伸阅读`。两种写法（`## 和其他关键词的关系` 或 `## 延伸阅读`）都合法。
> - 只要「中心问题、5-7 句主引用、关联关键词/延伸主题、5 个案例、5 个常见误解、总结」这些要素齐全、且关键判断能回溯 `buffett/` 原文，小节的命名与顺序可按主题调整。
> - 唯一仍属硬性结构的：必须有一个可独立扫读的 `## 主引用` 小节（5-7 句直接引用），不能只把原话揉进 `## 原文依据概览` 的叙述里。

写作顺序：

- [ ] 先检索 `buffett/` 原文。
- [ ] 再建立来源矩阵。
- [ ] 再建立原话卡片。
- [ ] 再归纳中心问题和核心观点。
- [ ] 再筛选 5-7 句主引用。
- [ ] 再整理案例、误解、延伸主题。
- [ ] 最后写正文。

禁止：

- [ ] 先写观点再找原话装饰。
- [ ] 写没有原文依据的判断。
- [ ] 公司文章写成百科。
- [ ] 人物文章写成传记流水账。
- [ ] 行业文章写成普通行业报告。
- [ ] 为了链接而过度链接每一次关键词出现。

## 9. 单篇文章执行流程

### 9.0 省 token 模式

后续继续执行 `docs/` 下的 todo 时，默认按以下方式处理：

- [ ] 只读当前条目需要的最少文件。
- [ ] 不展开大段背景材料。
- [ ] 验证只做精确匹配和结构检查。
- [ ] 不再重复回看已经确认过的旧文章。

对每篇文章重复执行：

- [ ] 在 `docs/article-index.md` 中登记文章。
- [ ] 确定文章类型和保存目录。
- [ ] 确定 slug 和文件路径。
- [ ] 写 frontmatter。
- [ ] 根据主题检索 `buffett/`，先找 15-25 条候选原话。
- [ ] 创建 `docs/source-matrices/{slug}.md`。
- [ ] 创建 `docs/quote-cards/{slug}.md`。
- [ ] 从候选原话中选 5-7 句主引用。
- [ ] 确认中心问题能被这些原话回答。
- [ ] 整理 3-5 个关联关键词。
- [ ] 检查关联关键词是否在 `docs/keyword-registry.md`。
- [ ] 整理 5 个左右案例，并为每个案例记录来源。
- [ ] 整理 5 个左右常见误解，并为每个误解记录纠正依据。
- [ ] 整理 5 个左右延伸阅读或相关主题。
- [ ] 按对应文章模板写初稿。
- [ ] 在正文首次出现的重要关键词上使用 `[[关键词]]`。
- [ ] 把文章保存到 `buffett/articles/` 下对应目录。
- [ ] 检查每个关键判断是否有 `buffett/` 原文依据。
- [ ] 检查文章类型是否正确。
- [ ] 补齐文章末尾关联关键词和延伸主题。
- [ ] 检查所有 `[[关键词]]` 都能在注册表找到。
- [x] 在 `docs/article-index.md` 中把状态更新为 `初稿完成`。
- [x] 完成最终核验后，把状态更新为 `已核验`。

## 10. 网站产品设计

### 10.1 信息架构

网站主要页面：

- [ ] 首页：展示知识库定位、核心分类、推荐阅读、搜索入口。
- [ ] 分类页：展示 11 个分类及分类下文章。
- [ ] 关键词词条页：展示定义、原文证据、案例、误解、反向链接、关系图。
- [ ] 文章详情页：展示正文、关键词链接、来源矩阵、关联阅读。
- [ ] 公司页：公司案例和相关关键词。
- [ ] 人物页：人物角色和相关思想。
- [ ] 行业页：行业经济特征和案例。
- [ ] 搜索页：按关键词、公司、人物、原文来源检索。

### 10.2 核心交互

- [ ] 点击正文中的 `[[关键词]]` 后跳转到关键词词条页。
- [ ] 在词条页显示所有引用该关键词的文章。
- [ ] 在词条页显示关联关键词。
- [ ] 在文章页右侧显示当前文章的关键词上下文。
- [ ] 支持阅读、图谱、来源三种视图。
- [ ] 支持搜索关键词、公司、文章标题。
- [ ] 支持从来源矩阵回到原文文件。

### 10.3 原型视觉方向

当前 HTML 原型的设计方向：

- [ ] 气质：温馨、理性、平常心。
- [ ] 文案基调：慢慢读，反复看，用原文校准判断。
- [ ] 视觉：低饱和暖纸色、沉稳绿色、茶色引用线。
- [ ] 布局：左侧分类与搜索，中间阅读区，右侧关键词上下文。
- [ ] 功能：阅读 / 图谱 / 来源 三视图切换。

设计 token：

- [ ] 背景纸色：`#f7f4ed`。
- [ ] 面板色：`#fffdf8`。
- [ ] 正文色：`#25302b`。
- [ ] 次级文字：`#6f756e`。
- [ ] 主绿色：`#486b55`。
- [ ] 柔和绿色：`#edf3ea`。
- [ ] 茶色引用线：`#9b7a44`。

布局要求：

- [ ] 桌面端采用三栏结构。
- [ ] 移动端改为单栏结构。
- [ ] 不做营销 landing page。
- [ ] 第一屏直接展示知识库使用界面。
- [ ] 保持资料密度，但避免压迫感。
- [ ] 所有文字不应遮挡或溢出容器。
